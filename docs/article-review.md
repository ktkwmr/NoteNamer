# 記事の内容確認（人間がやる）

記事は Claude が書き、**公開（main へのマージ）の前に人間が内容を確認**します（WEBAPP_BASELINE.md §10-7）。
PR を出すと Cloudflare のプレビュー URL ができるので、そこで実際のページを見て確認します。直したい点は PR のコメントか Claude への指示で伝えてください。

## 毎回見ること

| # | 観点 | 見るところ |
|---|---|---|
| 1 | 事実の正しさ | 分野の説明に間違いや言い過ぎがないか |
| 2 | アプリとの一致 | 記事の説明（ボタン名・手順・条件）がいまのアプリの動きと合っているか。画面写真が古くないか |
| 3 | 表の内容 | 表は計算で作っているので書き間違いはないが、選んだ例や結果が実際に自然か |

## 2026-11-07 複数ファイルの読み取りで直したところ

| # | 記事 | 確認してほしい点 |

| A | guide | 「楽譜を開く」に、ファイルが番号付きの一覧に並ぶ・ハンドルで並べ替え・「楽譜を読み取る」で 1 つの楽譜にする説明と、一覧の画面写真（app-list）を追加。読み取り中の画面写真なども撮り直した |

## 今回（2026-10-24、最初の記事 7 本）特に見てほしいところ

| # | 記事 | 確認してほしい点 |
|---|---|---|
| A | tempo-markings | 速度記号の「BPM の目安」の範囲は一般的な資料（英語版 Wikipedia などに載っている値）に頼った。資料によって違う。日本のメトロノームの目盛りと比べて違和感がないか。読み（カタカナ）と意味の訳も |
| B | tempo-markings | 「拍が 4分音符でないとき」の換算（♩. = 60 → ♩ = 90 など）と、アプリが数字をそのまま 4分音符として使うという説明 |

| F | musicxml | MusicXML の歴史（2004 年に Recordare、今は W3C Music Notation Community Group、最新版 4.0）。MuseScore のメニュー名（ファイル → 開く／エクスポート） |

### Claude による校閲（2026-10-25）で直したこと

| 記事 | 直したこと | 根拠 |
|---|---|---|
| guide・faq | 「Safari・Firefox・スマホにはまだ JSPI がない」は古かった。Android の Chrome 137・Firefox 153（2026-07）・Safari 27（2026-09）が対応済み。「動作確認は PC の Chrome・Edge だけ」に変更 | web-platform-dx の developer-signals、Mozilla の Bugzilla、WebKit のブログ |
| fix-errors・what-is-omr | 弱起（アウフタクト）の小節は短いのが正しいので、「!」が正しい場合があると追記。臨時記号は「同じ高さの音」ではなく「同じ線・間の音」に効く | 記譜の慣習。アプリの `score-model.mjs` は弱起の小節にも「!」を付ける |
| musicxml | 歴史を「2000 年から設計、2004 年に 1.0、2011 年に MakeMusic、2015 年から W3C」に。日本語の `duration` の説明の誤り（「divisions で割った数」）を直した。MIDI に「小節線の情報がない」は不正確（拍子は入る）なので、付点かタイか・連桁・段と声部に置き換えた | Wikipedia、MakeMusic の発表 |
| tempo-markings | 「多くの資料に載っている範囲」は言い過ぎ（資料によってかなり違う。機械式メトロノームでは Allegro 120〜168 など）と明記。Lento の訳を「遅く」に。Allegro moderato の説明を「2 つ目の言葉が 1 つ目を補う」に | 各種の速度記号の表 |
