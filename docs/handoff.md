# ドレミ付き楽譜メーカー 引き継ぎ資料（Claude Code 向け）

2026-11-08 · ktkwmr

> この資料は Claude Docs の引き継ぎ資料（2026-11-08 版）を Markdown にしたもの。最初のコミットに入れる（資料末尾の指示）。

## 概要

楽譜を撮るだけで、すべての音符に音名（ドレミ・C D E・도레미など）を付けた楽譜を作り、印刷・保存・共有できる Web アプリを作る。ktkwmr.com の 9 つ目のアプリとして公開する。

**対象ユーザー**：楽譜が読めない・苦手な人。ピアノを再開した大人、子どもの練習を見る親、合唱・吹奏楽の初心者、鍵盤ハーモニカやリコーダーの利用者。

**企画の根拠**（Cloudflare Web Analytics と Search Console、2026 年 10〜11 月の実績）

- 直近 21 日の訪問の約 3 分の 2（約 1,100 / 1,650）が Sheet Music Player。ほかのアプリは各 30〜60。
- 端末はスマホが約 8 割（iOS が最多、Android が次点）。
- 国は日本が約半分、残りはアメリカ・韓国・フィリピン・アルゼンチン・ルーマニア・トルコなどに分散。
- 流入元は 100% が「直接」。Google 検索のクリックは 28 日間で 0。運営者は SNS などで一切紹介していない。AI チャットからの紹介や、閉じたグループでの共有が主な入口と推定（未確認）。

**この結果から決めた設計の条件**

1. スマホで撮るだけ、10 秒以内に結果が出る
2. 言語に依存しない（音名の書き方を国ごとに選べる）
3. 結果を人に送れる（画像・PDF・印刷）
4. 一言で説明できる。冒頭に「無料・登録不要・ブラウザ内で処理」を明記する（AI に紹介されやすくするため）

## 結論：Sheet Music Player をベースにする

**Sheet Music Player（ktkwmr/SheetMusicPlayer）のリポジトリを丸ごとコピーして新しいリポジトリを作り、そこから作り変えるのが最も効率的。** 楽譜の読み取りから表示までの中核は全部そのまま使え、新しく作るのは「音名を付ける」「印刷・書き出す」部分だけになる。

**流用できるもの（ゼロから作ると数か月かかる部分）**

- ブラウザ内の読み取りエンジン：homr を Pyodide・onnxruntime-web で動かす仕組み（`omr-worker.mjs`、`engine/python/`、`scripts/build-engine.py`）
- iPhone 対策：JSPI の不具合よけ、メモリ不足対策（セッションの使い回し、共有メモリの上限、ワーカーの停止）。利用者の約半分が iPhone なので必須
- 読み取り結果の補正：`slursToTies`・`fixStrayTuplets`・`fixVoiceOverflow`・`expandMultiRests`（`score-model.mjs`）
- 画像・PDF・カメラの入力、複数ページ、OpenSheetMusicDisplay（OSMD）での楽譜表示
- 移調（`transposeXml`）、再生とカーソル、読み間違いを直す編集画面（`editor.mjs`）
- 英日の画面（`I18N`・`build-ja.mjs`）、記事ページの生成（`build-pages.mjs`）、PWA、`_headers`、`wrangler.jsonc`

**別の方式を採らない理由**

- *Sheet Music Player に機能として足すだけ*：アプリ名と入口のページが増えない。「楽譜にドレミを振るアプリ」として一言で紹介されにくく、初心者向けに画面を絞れない。
- *ゼロから作る*：上の読み取りエンジンと iPhone 対策を作り直すことになり、効率が悪い。
- *Sheet Music Player のエンジンを URL で共用する*：「アプリ同士を依存させない」というドメインの方針（ktkwmr/ktkwmr.com の README）に反する。

**コピーするときの注意**

- ライセンスは **AGPL-3.0** を引き継ぐ（homr が AGPL-3.0 のため。ベースラインの MIT にしない）。
- エンジン（約 122MB）はアプリごとに配信されるので、両方を使う人は 2 回ダウンロードする。許容する。
- エンジンと補正処理は 2 か所で維持することになる。どちらかで直した不具合は、もう一方にも移植する案を PR で出す。
- git の履歴は引き継がない（新しいリポジトリにファイルだけをコピー）。最初のコミットに「SheetMusicPlayer のどのコミットから作ったか」を書く。

## アプリ名・リポジトリ名の候補

**推奨は Note Namer（リポジトリ ktkwmr/NoteNamer、URL ktkwmr.com/notenamer/）。** 今のアプリと同じ「英語 2 語で機能が分かる名前」で、ドレミでも C D E でも当てはまる。日本語ページのタイトルは「Note Namer — 楽譜にドレミを振る」のように機能を添える。

| アプリ名 | リポジトリ / スラッグ | 良い点 | 気になる点 |
| --- | --- | --- | --- |
| Note Namer（推奨） | NoteNamer / notenamer | 短い。どの国の音名にも合う | 日本語では意味が伝わりにくい |
| Sheet Music Labeler | SheetMusicLabeler / sheetmusiclabeler | Sheet Music Player と対になる | 長い。labeler が伝わりにくい |

## 機能要件

**MVP は「撮る → 音名付きの楽譜が出る → 印刷・保存・共有」の一本道。** Sheet Music Player の機能のうち、この流れに要らないものは画面から外す。

### MVP

1. **入力**：Sheet Music Player と同じ（カメラ、画像、PDF、MusicXML、12 ファイルまで、並べ替え）。
2. **音名の表示**：すべての音符の下に音名を書く。和音は縦に積む（高い音が上）。休符には書かない。大譜表は譜表ごとに書く。
3. **音名の書き方**（既定はブラウザの言語から決め、保存する）
   - ドレミ（カタカナ）：ド レ ミ ファ ソ ラ シ（ja の既定）
   - どれみ（ひらがな）：ど れ み ふぁ そ ら し
   - Letter names：C D E F G A B（en の既定）
   - Do Re Mi（固定ド）：Do Re Mi Fa Sol La Si
   - 도레미：도 레 미 파 솔 라 시
4. **♯・♭**：調号と臨時記号（小節内で持続、タイも考慮）を反映し、「ファ♯」「B♭」のように書く。ダブルシャープ・ダブルフラットも対応。
5. **文字の大きさ**：小・中・大の 3 段階。
6. **読み間違いの修正**：Sheet Music Player の編集画面をそのまま使う。直したら音名も更新。
7. **再生**：カーソル付きの再生とテンポ変更。「音名が合っているか」を耳で確かめるために残す。
8. **移調**：残す。音名は移調後の高さで書く。
9. **書き出し**
   - 印刷（A4 縦、画面のボタン類は印刷しない。OS の印刷画面から PDF 保存もできる）
   - 画像（PNG、ページごと）を保存
   - 共有：Web Share で画像を送る。対応しないブラウザでは保存を案内
   - MusicXML の保存（音名を歌詞として入れた版）。MuseScore などで開ける
10. **画面から外すもの**：MP3・MIDI の書き出し、パートの強調・消音、ループ。必要になったら戻す。

### 後続（MVP のあと、反響を見て順に）

- 移動ド（調の主音をドとする）
- 音符の玉の中に音名を書く表示（子ども向けの「ドレミ音符」）
- 音の高さごとの色分け
- 元の写真に音名を重ねて表示・印刷（homr が出す音符の位置を使う。可否は未確認）
- オクターブ付きの表記（C4、ド′ など）、ドイツ式（H）などの書き方の追加
- Sheet Music Player の画面に「音名付きで印刷」へのリンクを置く（Sheet Music Player 側の別 PR）

## 技術方針

**音名は MusicXML の各音符に歌詞（`<lyric>`）として差し込み、OSMD に描かせる。** 文字の位置や音符の間隔を OSMD が自動で調整し、印刷や MusicXML の保存もそのまま効くため。

### 表示までの流れ

1. 読み取り：`omr-worker.mjs`（homr）→ MusicXML。変更なし
2. 補正：`expandMultiRests` → `slursToTies` → `fixStrayTuplets` → `fixVoiceOverflow`。変更なし
3. `state.xml` に保存（音名を含まない元の XML）。編集画面もこれを使う
4. 移調：`transposeXml`。変更なし
5. **新規** `addNoteNames(xml, system)`：移調後の XML の各音符に音名の `<lyric>` を足す（表示・印刷・書き出し専用。`state.xml` には戻さない）
6. OSMD で描画 → 画面・印刷・PNG

### 音名の決め方（`note-names.mjs`、新規。DOM に依存しない純粋な関数にする）

- 各 `<note>` の `<pitch>` の `<step>` と `<alter>` から決める。MusicXML の `<alter>` は調号・臨時記号を反映した実際の高さ。Sheet Music Player の再生（`score-model.mjs` の `parseScore`）も `<alter>` だけで正しく鳴っているので、homr の出力も調号込みと考えてよい。最初に調号付きのテスト楽譜で確かめる。
- `<alter>` の記号：+1 = ♯、−1 = ♭、+2 = 𝄪、−2 = 𝄫。音名の後ろに付ける（ファ♯、B♭）。
- 書き方ごとの対応表を 1 か所に持つ（`katakana` / `hiragana` / `letter` / `solfege` / `korean`）。
- 書かないもの：休符、`<unpitched>`（打楽器）、タイでつながった後ろの音（`<tie type="stop">` だけの音）。装飾音は書く。
- 和音（`<chord/>` 付きの音）：高い音から順に `<lyric number="1">`、`"2"`… として縦に並べる。
- 元の楽譜に歌詞があるとき（MusicXML を開いた場合など）は、表示では元の歌詞を消して音名だけにする。

### 歌詞方式で不十分なときの代わり

和音の重なりや大譜表での位置が OSMD の歌詞ではきれいに出ない場合は、OSMD の描画後に音符の位置（`GraphicSheet` の各音符の `PositionAndShape`）を取り、SVG の文字を重ねる方式に切り替える。後続の「玉の中に音名を書く」表示にはこの方式が必要になる。最初の PR で両方を小さく試し、画面写真を添えてどちらにするか判断する。

### 印刷・画像

- 印刷と PNG は、画面用とは別に OSMD を `pageFormat: "A4_P"` で描いてページに分ける。
- PNG は各ページの SVG をキャンバスに描いて作る（外部ライブラリを足さない）。
- 楽譜のタイトルと「このアプリで作成」の小さな表示（URL 付き）をページの下に入れる。共有された画像からアプリに来られるようにするため。設定で消せるようにする。

### テスト

- `tests/note-names.test.mjs`：書き方 5 種類×♯♭、調号（ト長調のファ♯、ヘ長調のシ♭）、臨時記号、タイ、和音、休符、移調後の綴り。
- 既存の `tests/score-model.test.mjs` はそのまま通す。
- Playwright：テスト楽譜（「歓喜の歌」、大譜表、調号付き）で「読み取り → 音名付き表示 → 印刷プレビュー → PNG 保存」を通す。

## 画面・記事・差別化

**初めて開いた人が、自分の楽譜がなくても 10 秒で「音名付きの楽譜」を見られる画面にする。**

### 画面

1. **開いたとき**：一行の説明（「楽譜を撮ると、すべての音符にドレミを振ります」）と「無料・登録不要・楽譜はアップロードされません」。大きな「写真を撮る」「ファイルを選ぶ」と、「見本で試す」。
2. **見本で試す**：歓喜の歌（パブリックドメイン）の読み取り済み MusicXML をすぐ表示する。エンジンのダウンロードを待たせない。
3. **読み取り後**：音名付きの楽譜。上に「書き方」「文字の大きさ」。下に「印刷」「画像を保存」「共有」を大きく。「再生」「移調」「直す」は一段小さく。
4. **スマホ優先**：利用者の約 8 割がスマホ。幅 375px でボタンが片手で押せること。

### 競合「ドレミえる」との差

[ドレミえる](https://doremiru0.github.io/doremieru/guide.html)は、五線の位置を利用者がスライダーで合わせ、音符の範囲をマーカーでなぞる方式。ガイドにはカメラ・大譜表・♯♭・再生・印刷の記載がない（2026-11-08 にガイドページで確認）。本アプリは次の 3 点を打ち出す。

- 撮るだけ（五線の位置合わせがいらない）
- ♯・♭を正しく反映（調号を無視したドレミは間違いになる）
- 印刷・画像でそのまま使える。音も鳴る

## 作業手順・受け入れ基準・指示文

**1 PR に 1 つの目的で、次の順に進める。** 各 PR は Cloudflare のプレビューで確かめてから squash マージする（ベースラインどおり）。

### 手順

0. **人間**：アプリ名を決め、空の公開リポジトリ（例：ktkwmr/NoteNamer）を作り、Claude Code のセッションに SheetMusicPlayer・webapp-baseline・ktkwmr.com と一緒に追加する。
1. **PR 1：コピーと改名**。SheetMusicPlayer の main をコピーし、スラッグを全部置き換える（`wrangler.jsonc` の Worker 名と Route、`public/` のフォルダ名、`<base href>`、`sw.js` とエンジンのキャッシュ名、`localStorage`・IndexedDB のキー、manifest、`I18N`、README、CLAUDE.md、`docs/baseline-status.md`）。書き出し（MP3・MIDI）・パートの強調・ループを画面から外す。この時点で「新しいパスで読み取り → 表示 → 再生ができる」ことを確かめる。
2. **PR 2：音名の表示**。`note-names.mjs` とテスト、`addNoteNames`、表示への組み込み。歌詞方式と SVG 重ね方式を小さく試し、画面写真を PR に添えて人間に選んでもらう。
3. **PR 3：設定と見本**。書き方・文字の大きさの選択（保存する）、「見本で試す」、開いたときの画面。
4. **PR 4：印刷・画像・共有・MusicXML**。
5. **PR 5：記事**（英日。人間がプレビューで内容を確認してからマージ）。アイコン・OG 画像も作る。
6. **公開**：本番デプロイ。ktkwmr/ktkwmr.com に `home.mjs`（`APPS`・`ICON`）と `robots.txt` を直す PR。人間が Search Console に sitemap を送る。
7. **その後**：Sheet Music Player にこのアプリへのリンクを置く PR。

### 受け入れ基準（MVP）

- [ ] iPhone の Safari で、楽譜を撮ってから音名付きの楽譜が出るまで、メモリ不足にならずに通る
- [ ] 「見本で試す」はエンジンなしで 3 秒以内に音名付きの楽譜が出る
- [ ] ト長調の楽譜でファがすべて「ファ♯」「F♯」になる。臨時記号は小節の終わりまで効く
- [ ] 大譜表で、上下両方の譜表に音名が付き、和音の音名が重ならない
- [ ] 書き方 5 種類を切り替えられ、次に開いたときも残っている
- [ ] 移調と編集のあと、音名が新しい高さに合う
- [ ] A4 に印刷でき、ボタン類が印刷されない。PNG 保存と Web Share での共有ができる
- [ ] `npm test` と `build-ja.mjs --check`・`build-pages.mjs --check`・`build-engine.py --check` が通る
- [ ] 楽譜がサーバーに送られない（ネットワークで確認）
